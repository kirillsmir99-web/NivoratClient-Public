# Сравнительный анализ: PreEmptive DashO vs Zelix KlassMaster (ZKM) для NivoratClient (Phase 27)

## 1. Введение и контекст выбора

В соответствии с техническим заданием, **основным production-обфускатором** для NivoratClient выбран **PreEmptive DashO (Standard Java mode)**.
Тем не менее, в индустрии коммерческой защиты Java-приложений и Minecraft-клиентов широко известен **Zelix KlassMaster (ZKM)** как специализированный инструмент с экстремально агрессивным уклоном в защиту математики и алгоритмов.

Данный документ представляет собой техническое исследование применимости ZKM для NivoratClient и анализ рисков создания цепочки «DashO + ZKM».

---

## 2. Сравнительная матрица возможностей защиты

| Вектор защиты | PreEmptive DashO (Текущий выбор) | Zelix KlassMaster (ZKM) | Влияние на NivoratClient |
|---|---|---|---|
| **Переименование идентификаторов (Renaming)** | Высокое (Short non-mnemonic, Overload induction) | Экстремальное (Unprintable characters, Unicode homoglyphs) | DashO достаточен; Unicode-имена часто вызывают баги в логах Fabric. |
| **Control Flow Obfuscation** | Высокое (Switch flattening, Opaque predicates) | Экстремальное (Jump table scrambling, Exception flow mixing) | ZKM сильнее ломает декомпиляторы, но может снижать FPS в циклах. |
| **Шифрование строк (String Encryption)** | Динамическое, раздельное по уровням классов | Многоуровневое, per-class ключи | Примерно паритет по защищенности. |
| **Шифрование целочисленных констант (Int/Long)** | Базовое | **Экстремальное (Bitwise math encoding)** | **Преимущество ZKM** для PID-регуляторов и формул AutoCart. |
| **Скрытие ссылок (Reference Obfuscation)** | Ограниченное (для Java 21) | Продвинутое (через `invokedynamic` и reflection) | Риск: `invokedynamic` может конфликтовать с Fabric Intermediary. |
| **Package Collapse / Flattening** | Поддерживается | Агрессивное слияние пакетов в один | Риск поломки Fabric entrypoints и путей к Mixin JSON. |
| **Интеграция с Gradle и CI/CD** | Официальный Gradle Plugin, нативная поддержка | CLI / Script-based запуск | DashO значительно удобнее автоматизировать в CI/CD. |
| **Совместимость с Java 21 / Bytecode Verifier** | 100% стабильность на JVM HotSpot 21 | Требует тщательной тонкой настройки флагов verifier | DashO безопаснее для релиза на широком парке ПК игроков. |

## 3. Критические риски применения Zelix KlassMaster в Fabric 1.21.11

1. **Конфликт с Mixin Processor**:
   - Fabric Mixins производят трансформацию байткода на этапе загрузки классов (`ClassTolerantClassLoader` / Knot).
   - Если применить reference obfuscation или агрессивный exception-flow из ZKM к классам, являющимся целями инжекций (`@Inject`, `@Redirect`, `@Shadow`), Mixin runtime падает с фатальной ошибкой `InvalidMixinException: Target class was corrupted`.
2. **Проблема двойной обфускации (Chaining Obfuscators: DashO + ZKM)**:
   - Попытка последовательно прогнать JAR через DashO, а затем через ZKM (или наоборот) категорически **запрещена**.
   - Двойное запутывание графа вызовов почти гарантированно приводит к превышению лимита размера байткода методов (64 KB limit в спецификации JVM), генерации некорректных `StackMapTable` и падению клиента с ошибкой `java.lang.VerifyError`.
3. **Падение производительности в циклах отрисовки и тика**:
   - Шифрование констант в ZKM превращает каждую константу `1.25` в выражение из 10 побитовых операций (`(((x ^ 0x4B) << 2) + ...)`).
   - Применение этого механизма в `Render2D` или `ArcMotionProfile.forward()` уничтожает прирост производительности от JIT C2 компилятора.

## 4. Архитектурная рекомендация

1. **Для основного дистрибутива**:
   - **Оставить PreEmptive DashO** единственным и безальтернативным обфускатором продакшн-релизов. Он обеспечивает идеальный баланс между взломостойкостью, производительностью и стабильностью Fabric ABI.
2. **Экспериментальный профиль `MAX_STATIC` (Будущее расширение)**:
   - Если в будущем потребуется сверхзащита отдельных изолированных алгоритмических классов (например, нового закрытого нейросетевого модуля прицеливания), ZKM можно использовать **локально**:
   - Оформить модуль как отдельный внутренний `.jar` без Fabric/Mixin зависимостей.
   - Обработать только этот мини-JAR через ZKM с шифрованием констант.
   - Внедрить скомпилированный результат в основной проект до этапа сборки DashO.
