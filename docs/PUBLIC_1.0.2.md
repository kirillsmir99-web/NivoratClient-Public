# PUBLIC 1.0.2 — ввод, PEARL и нативные списки

Исходный снимок перед этой доработкой: `backup/bindings-hud-20261001-094145/source-before.zip`. Донорские проекты Nivorat и «НОВЫЙ ПВП РЕНДЕР» не изменялись. В продукт не включаются игровые helper-классы из `tools/visual-smoke`.

## Изменения

- Захват бинда завершается после назначения; события мыши доходят до ожидающего виджета раньше перетаскивания окна и контекстного меню. Отдельные Ctrl/Shift/Alt правильно сопоставляются при нажатии самой клавиши-модификатора. Tab, Caps Lock и G не имеют специальных запретов.
- При занятом бинде открывается нативное окно с названием конфликтующей функции. Отмена сохраняет оба назначения; подтверждение переносит бинд и обновляет диспетчер. Esc/Backspace/Delete снимают назначение при захвате.
- Мышь использует стандартные коды GLFW 0–7. Дополнительные кнопки MMO-мыши, которые драйвер выдаёт как клавиатурные клавиши, назначаются как эти клавиши. Прямой доступ к двенадцати аппаратным кнопкам через стандартный GLFW не заявляется.
- Click PEARL открывает собственный инвентарь перед извлечением PEARL из основного инвентаря. Извлечение, закрытие, бросок и возврат разделены тиками. Возврат проверяет владельца, мир, screen handler и содержимое слотов, чтобы не перезаписать изменённый пользователем предмет.
- AutoPearlCatch пересчитывает перехват перед броском ветра с учётом перемещения игрока, вертикальной скорости в воздухе и физики PEARL 1.21.11. Геометрическая сумма заменяет многократную пошаговую симуляцию при поиске времени встречи. Полуавтомат сохраняет ручное прицеливание.
- HP Reaper получил нативный редактор позиции, ряд надетой брони, переключаемую разницу HP и сердечки низкого здоровья из шрифта донорского визуала. Порог появления настраивается.
- Auto GG получил нативный список: добавление, редактирование, удаление и избранные фразы. Автоматическая отправка выбирает избранные; выбранная избранная фраза остаётся основной при выключенном случайном порядке. Вместимость колеса остаётся восемь фраз.
- Cooldown получил поиск и выбор предметов по локализованному названию или registry ID. Переименованные предметы хотбара можно выбирать отдельно. Группы `USE_COOLDOWN` сохраняются вместе с реальным стеком и его названием; разные группы одного базового предмета не объединяются. Выбранные предметы могут показывать короткие реальные кулдауны ниже общего порога. Таймеры для предметов без игрового/серверного кулдауна не выдумываются.
- Закреплённые темы сохраняются в `nc-visual.json` и показываются первыми. Пользовательские темы остаются в списке.
- Выпадающие списки рисуются отдельным верхним слоем с плотным фоном; подписи и значения соседних настроек не рисуются поверх них.
- Исправлен GPU-контракт палитры: шейдер читает 56 `vec4` на слот, а Java раньше выделяла только восемь. Каждый слот теперь полностью инициализируется, удалены чтения невыделенной памяти, которые давали белые стеклянные панели. Соответствие размера и шага проверяется отдельным тестом.

## Воспроизведение проверок

JDK 21. В Windows с длинным кириллическим путём используется короткий путь `Q:` к текущему проекту и `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/Windows/Temp`.

```
gradlew test remapJar --no-daemon
gradlew -I tools/public-visual-smoke.init.gradle publicVisualSmoke -PmechanicsSmoke --no-daemon
gradlew -I tools/public-visual-smoke.init.gradle publicVisualSmoke -PrevisionSmoke --no-daemon
gradlew -I tools/public-visual-smoke.init.gradle publicVisualSmoke -PpearlCatchSmoke --no-daemon
```

Игровые проверки запускают PUBLIC JAR с копией набора модов пользователя в `build/visual-smoke/game`, ограничивая JVM одним доступным процессором. Они не вмешиваются в пользовательский игровой сеанс. Набор тестов, журналы успешных прогонов, установленный SHA-256 и путь резервной копии фиксируются в `docs/native-visual-install.json` после завершения проверки.

Открытый экран инвентаря и штатный interaction manager не гарантируют совместимость с любым сторонним античитом. Проверка встроенного сервера отделяется от многопользовательской проверки после перезапуска лаунчера.
