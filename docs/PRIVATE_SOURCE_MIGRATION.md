# NivoratClient: Руководство по миграции публичного репозитория в закрытый (Phase 28)

## 1. Контекст проблемы и текущий статус

Репозиторий `kirillsmir99-web/NivoratClient-Public` исторически находился в публичном доступе на GitHub.
В связи с этим владелец проекта должен исходить из фундаментального принципа информационной безопасности:

> ⚠️ **АКСИОМА ПУБЛИЧНОГО ИСТОРИЧЕСКОГО КОНТЕКСТА**:
> Любой коммит, файл или строчка кода, которые когда-либо были запушены в публичный репозиторий, **уже скомпрометированы** (могли быть скачаны поисковыми пауками, форкнуты пользователями или сохранены в архивах вроде Wayback Machine и GitHub Archive).
> 
> Простое переключение флага репозитория с **Public** на **Private** в настройках GitHub:
> 1. Скрывает код от будущих случайных посетителей.
> 2. **НЕ отзывает** уже скачанные копии у злоумышленников.
> 3. Сохраняет старую историю коммитов.

Поэтому цель системы защиты NivoratClient — обеспечить неприкосновенность **будущих версий, новых алгоритмов (AutoCart, Arc, Mace), закрытых ноу-хау и скомпилированного релизного JAR**.

## 2. Рекомендуемые архитектурные стратегии миграции

Для долгосрочной защиты коммерческого продукта владельцу рекомендуется выбрать один из двух путей:

### Стратегия A: Создание чистого приватного репозитория (Рекомендуется)

Наиболее чистый, надежный и профессиональный подход для закрытых клиентских решений.

1. **Создание нового репозитория**:
   - Создается чистый приватный репозиторий `kirillsmir99-web/NivoratClient` (или `NivoratClient-Enterprise`).
   - Исходный публичный репозиторий `NivoratClient-Public` переводится в режим **Public Read-Only Archive** либо очищается от закрытых алгоритмов и превращается в открытый SDK (Public API).
2. **Экспорт кодовой базы без «токсичной» публичной истории**:
   - Текущее стабильное состояние (включая настроенный пайплайн ProGuard 7.9.1, доменное маскирование чисел, аннотации Gson и минификатор шейдеров) заливается в новый приватный репозиторий единым начальным коммитом (`Squash / Initial Commit`).
   - Никакие старые драфты формул и удаленные когда-то конфиги не «всплывут» при сканировании истории коммитов.
3. **Разделение веток**:
   - Вся будущая коммерческая разработка ведется исключительно в новом приватном репозитории.

---

### Стратегия B: Модульное разделение кодовой базы (Multi-Repo / Private Submodule)

Если планируется поддерживать открытую версию для комьюнити (Community Edition) и платную/закрытую версию (VIP / Commercial Edition):

1. **Open-Source ядро (Public)**:
   - Базовый рендеринг GUI, Fabric-хуки, интеграции, открытые модули HUD.
2. **Закрытый модуль алгоритмов (Private Submodule / Maven Artifact)**:
   - Пакеты `dev.nivorat.arc.*`, `dev.mace.*`, предикторы и закрытые математические модели выносятся в отдельный закрытый репозиторий `nivorat-arc-private`.
   - На этапе сборки приватная зависимость подключается через локальный maven или private subproject, компилируется и защищается через ProGuard и доменные маски.

## 3. Правовые аспекты и лицензирование (Phase 11)

В текущей кодовой базе исторически присутствовали ссылки на лицензию MIT. При переходе на коммерческую или закрытую модель владения кодом необходимо юридически и технически разграничить лицензии:

### 3.1. Собственный код Nivorat
- **Лицензия**: Собственный код мода (GUI, модули, математика Arc, шейдеры) объявляется **Proprietary / All Rights Reserved** (или специальной пользовательской лицензией EULA Nivorat Client).
- В `fabric.mod.json`:
  ```json
  "license": "Proprietary",
  ```
  *(Примечание: Fabric Loader корректно воспринимает строковый идентификатор `"Proprietary"`)*.

### 3.2. Сторонние компоненты (Third-Party / Nested JARs)
- Проект содержит вложенный JAR-мод `ClientSpoofer-1.21.11-1.4.0.jar`, распространяемый под лицензией MIT.
- **Инвариант сохранности**: Лицензия MIT автора ClientSpoofer обязана оставаться в `META-INF/licenses/LICENSE-ClientSpoofer.txt`! Ни в коем случае нельзя удалять копирайты авторов открытых библиотек или присваивать авторство вложенных открытых модов.
- Автоматический скрипт `verifyProtectedJar` гарантирует сохранение лицензионного файла в итоговом дистрибутиве.

## 4. Чек-лист безопасности при переходе в Private

Перед тем как публиковать будущие закрытые версии:

- [x] **Проведен аудит секретов**: в репозитории отсутствуют приватные ключи подписи JAR, пароли от хранилищ ключей (Keystore), вебхуки Discord и токены доступа.
- [x] **Изоляция симметричных ключей**: ключ в `activity.client.util.Obf` задокументирован как утилитарный ключ для сокрытия JSON-пресетов от случайного редактирования пользователем, а не криптографический секрет лицензирования.
- [x] **Защита байткода**: настроен ProGuard 7.9.1 с многоуровневыми правилами защиты, маскированием констант и шифрованием строк, гарантирующий, что будущие изменения в `dev.nivorat.arc.*` будут скрыты от декомпиляции.
- [x] **Минификация шейдеров**: из всех 163 шейдерных файлов вычищены отладочные комментарии разработчиков.
- [x] **Сохранность внешних контрактов**: Gson-поля аннотированы через `@SerializedName`, что обеспечивает переносимость конфигов между старыми и новыми версиями.
