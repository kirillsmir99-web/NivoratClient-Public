# NivoratClient: локальная интеграция и остановка

Проверено 01.10.2026: Minecraft 1.21.11, Java 21.0.10. Автор — Nivorat. Исходники доноров не изменялись. Резервная копия перед изменениями: `backup/ecosystem-stop-20261001-201427`.

## Что изменено

- В разделе оформления меню добавлена кнопка «Капитуляция»: удержание левой кнопки мыши две секунды с видимым прогрессом. Отпускание, потеря фокуса, уход с кнопки, закрытие экрана и нажатие клавиши отменяют подтверждение. Перетаскивание с Shift не запускает остановку.
- Остановка очищает очередь отложенных действий, завершает действия модулей, освобождает удерживаемое использование предмета, слоты и боевые блокировки, прекращает калибровку, отключает обработчики модулей и их HUD до перезапуска. Совместимые дополнения получают однократный локальный callback остановки.
- Уже отправленные серверу пакеты удалить нельзя. JAR остаётся загруженным, обычная работа Minecraft и его соединения сохраняются. Это остановка собственных модулей, а не выгрузка Fabric или удаление истории.
- Сохранённые пресеты и буфер обмена не удаляются. Принудительный `System.gc()` убран. После остановки настройки не перезаписываются очищенным состоянием.
- Сохранение визуальных настроек теперь включает зарегистрированные приватные параметры звука. Значения проверяются по типу и допустимому диапазону; некорректная запись не препятствует загрузке остальных. Запись выполняется через временный файл. Слушатели во время загрузки не перезаписывают тему.
- Разделы «Оформление», «Меню клиента» и «Звуки клиента» используют русский перевод. Технические имена существующих настроек сохранены для совместимости.

## Контракт интеграции

Используется локальная точка входа Fabric `nivorat:settings_v1`. Никаких HTTP-запросов, API-ключей или серверных сообщений для обнаружения дополнений нет. Обнаружение происходит в `CLIENT_STARTED`, после инициализации клиентов.

Адаптер — класс с интерфейсом `Supplier<Map<String, Object>>`, зарегистрированный в `fabric.mod.json`:

```json
{"entrypoints":{"nivorat:settings_v1":["example.VisualSettingsProvider"]}}
```

Возвращаемый дескриптор:

| Ключ | Тип и назначение |
| --- | --- |
| `version` | `Integer`, строго `1` |
| `modId` | Реальный ID мода, предоставившего точку входа |
| `sections` | Список до 16 описаний разделов |
| `stop` | Необязательный `Runnable`: остановка принадлежащих дополнению действий |

Каждый раздел содержит `group` (`appearance`, `menu` или `sounds`), непустые `titleRu` и `titleEn` длиной до 80 символов и `open` типа `Function<Screen, Screen>`. Фабрика получает родительский экран и должна вернуть отдельный экран настроек, который возвращает пользователя к родителю при закрытии. Если адаптер повреждён или фабрика выбрасывает исключение, локальный раздел сохраняется либо восстанавливается. При нескольких владельцах одной группы выбор детерминирован по ID провайдера.

NivoratClient также публикует необязательные `read: Supplier<Map<String,Object>>` и `apply: Consumer<Map<String,Object>>` для снимка и применения параметров группы. Текущий потребитель маршрутизирует экраны; автоматическая синхронизация файлов тем между модами ещё не реализована. Все callbacks должны выполняться в клиентском потоке. Живое подключение/отключение JAR не поддерживается.

В самостоятельном запуске все настройки остаются в NivoratClient. При наличии проверенного адаптера скрываются только дубли оформления, меню и звуков; боевые модули и HUD не передаются другому моду. В будущем PVE должен использовать согласованный контракт и собственные группы возможностей, не перехватывая боевые функции клиента.

Текущий Nivorat Visual ещё не предоставляет этот адаптер. Совместный запуск двух JAR с объединёнными настройками пока не подтверждён. Данный этап готовит контракт и маршрутизацию без изменений исходников Visual. Идентификаторы сохранения пока основаны на именах полей: при обфускации эти поля необходимо сохранять либо отдельно внедрить стабильные ID и миграцию.

## Что используют разработчики

- [Fabric entrypoints](https://wiki.fabricmc.net/documentation:entrypoint): необязательная локальная интеграция модов. Этот подход применён здесь.
- [YACL](https://github.com/isXander/YetAnotherConfigLib): декларативное построение настроек. Для нашего собственного рендера использованы принципы проверки значений и отделения хранения от экрана; библиотека не добавлялась.
- [Mod Menu](https://github.com/TerraformersMC/ModMenu): стандартные фабрики экранов настройки. Полезно как следующая дополнительная точка открытия нашего меню; зависимость сейчас не добавлялась.
- [ClientSpoofer](https://github.com/FabiPunktExe/ClientSpoofer): ограничение раскрытия бренда и списка модов. Это средство приватности, не оптимизатор FPS и не гарантия обхода проверок сервера.
- [Sodium](https://github.com/CaffeineMC/sodium): специализированная оптимизация рендера. Его установку следует отдельно проверять на совместимость с нашим стеклянным рендером.
- [Java Flight Recorder](https://docs.oracle.com/en/java/javase/21/troubleshoot/troubleshoot-performance-issues-using-jfr.html): измерение CPU, аллокаций, GC и блокировок перед оптимизацией. Предыдущий профиль не является замером FPS нынешней сборки.

Следующие полезные шаги: адаптер Visual, проверка совместного запуска, устойчивые ID настроек для обфускации, отдельные сценарии профилирования меню и боевых модулей на слабом ПК. Невидимость для античита не является свойством этого контракта и не проверялась.
