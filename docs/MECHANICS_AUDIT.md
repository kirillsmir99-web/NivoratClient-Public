# Проверка механик PUBLIC 1.0.1

Исходники: текущий клиент «Работа с GUI». Kimiko и «НОВЫЙ ПВП РЕНДЕР» не изменялись. Перед правками сохранены полный исходный снимок и бинарный Git diff в `backup/mechanics-20261001-024433/`.

## Исправленные причины сбоев

| Участок | Причина | Изменение |
| --- | --- | --- |
| ClickPearl | Диспетчер вызывал `onTick`, хотя мод реализует `onClientTick`; задержанный бросок и возврат не выполнялись | Единый вызов `onClientTick`, проверка предмета и активного контейнера, блокировка последовательности, безопасный возврат и отмена |
| AutoPearlCatch | Незавершённый поворот зависел от кадров; не проверялся предмет перед следующим броском | Продвижение интерполяции на тиках, предел времени, снимок режима, проверки руки/кулдауна и восстановление слота |
| AutoStunSlam | Полуавтомат сам выполнял удары; ожидание второго удара игнорировало таймер; искусственно сбрасывался локальный cooldown атаки | Полуавтомат ожидает ручные удары, автомат соблюдает задержки, удалён искусственный сброс, проверяются оружие и реальная дальность игрока |
| AutoShieldbreaker | Проверка расстояния до глаз отвергала достижимую точку тела; случайная задержка не учитывала настройку | Проверка попадания в коробку цели, предел атрибута дальности, настроенные задержки и проверка выбранного топора |
| AutoCart | Результаты взаимодействий игнорировались; событие установки отправлялось дважды; отмена могла оставить отложенное восстановление и блокировку | Проверка результата и предмета перед переходом, одно событие, немедленная отмена, привязка к игроку/миру, предел длительности |
| CartRefill | Общий диспетчер останавливался при открытии инвентаря самой функцией | Разрешены тики только для её собственного экрана инвентаря; другие боевые действия при GUI приостанавливаются |
| WaterDrop | Возврат предмета мог использовать handler другого контейнера или нового игрового сеанса | Проверка игрока/мира, отложенная очистка при чужом контейнере, возврат выбранного слота |
| Общие задержки | 15–35 мс после деления на 50 превращались в ноль тиков | Округление вверх; минимум один тик; ограниченная гауссовская выборка при включённой рандомизации |

AutoSpear и AutoMace сохраняют свои рабочие последовательности; общий диспетчер и очистка применяются также к ним. Остальные контроллеры просмотрены на переходы состояний и действия с инвентарём. Это не доказательство прохождения каждого игрового сценария каждого модуля.

## Обучение AutoCart

Модель обучает параметры движения камеры и задержек ручной последовательности «лук → рельс → вагонетка». Выбор места по траектории стрелы остаётся баллистическим расчётом; нейросеть не объявляется обученным распознавателем целей.

* Сохраняются веса **и смещения**; формат профиля — 3, старый формат 2 читается.
* Файл заменяется атомарно. Обучение помечает профиль изменённым; периодическое сохранение ограничено 30 секундами, вместо записи каждых 50 кадров.
* Движение снимается не чаще 20 раз в секунду. GUI, разрывы времени и автоматические боевые повороты исключены из обучения.
* Калибровка требует минимум 20 образцов движения и по три сопоставленных интервала установки. Пустая пятиминутная сессия не включает «Обученный» пресет.
* Устранён повторный учёт отпускания лука. Взаимодействия установки учитываются после принятого результата клиентского interaction manager.
* Неконечные обучающие значения отвергаются; рабочие массивы переиспользуются внутри синхронизированных методов.

## Проверки и пределы результата

Новые тесты проверяют уменьшение ошибки обучения, сохранение результата после загрузки, отклонение NaN/Infinity, отказ пустой калибровки и границы задержек. Общий набор: 726 тестов, ноль ошибок/падений на проверенном исходном состоянии.

`tools/visual-smoke/MechanicsSmoke.java` запускается против собранного PUBLIC JAR в изолированном Minecraft 1.21.11 с копией пользовательского набора модов. Проверены фактический снаряд перла на встроенном сервере, возврат слота через общий диспетчер, отмена при чате, серверная установка TNT-вагонетки и освобождение блокировок. Итоговый журнал PUBLIC 1.0.1: `build/public-1.0.1-mechanics-final-v2.log`; результат — `PASSED mechanics`. Helper очищает свои тестовые вагонетки перед сценарием; неуспех или отсутствие результата теперь завершают задачу Gradle ошибкой.

Полный прогон нативного GUI PUBLIC 1.0.1 также завершён: `build/public-1.0.1-final-validation-v2.log`. Установка и SHA-256 записаны в `docs/native-visual-install.json`; старый пользовательский JAR и найденные конфиги сохранены в `backup/public-1.0.1-20261001-090913/`.

Для воспроизведения: JDK 21, `gradlew test remapJar --no-daemon`; игровой сценарий — `gradlew -I tools/public-visual-smoke.init.gradle publicVisualSmoke -PmechanicsSmoke --no-daemon`. Отдельный GUI-сценарий запускается той же задачей без `-PmechanicsSmoke`. Игровой helper находится вне исходников продукта и не включается в PUBLIC JAR.

Проверки встроенного сервера не подтверждают совместимость каждого режима с каждым сторонним сервером. Рандомизация задержек не гарантирует принятие действий античитом. Замер FPS для любых слабых компьютеров и универсальная работоспособность всех функций не заявляются.
